## 去重原则

1. 先以原始仓库当前快照为候选清单，再用旧站逐篇核对历史发布状态。旧站文章是对照材料，不是覆盖原始正文的第二份权威副本。
2. 不因作者相同就合并文章。相同作者在夏令营和预推免目录中的内容通常是不同经历，除非人工确认正文实际为同一篇。
3. 只有在标题、作者、正文主体和附件均确认是同一份内容时才去重；优先保留信息更完整、来源更明确的副本，并在迁移清单中记录另一个来源路径和旧链接。
4. 标题相近、学校相近或包含相同段落不能单独作为删除依据。无法确认时保留两篇，交由维护者决定。
5. 去重不得通过润色或拼接正文实现。无论选择哪一份，正文都保持原文；只允许增加或调整 YAML 文件头，以及为新目录修正必要的相对资源路径。

## 文章目录与 YAML 规则

每篇最终公开的文章使用一个目录，文章正文、封面、正文图片和附件放在同一目录或其子目录中：

```text
src/content/experiences/2025/<stable-id>/
  index.md
  cover.*                 # 有明确封面时使用
  assets/                 # 正文图片和已审核附件，可按来源分组
```

- `applicationYear` 对这些 2025 年文章填写 `2025`；新投稿必填，历史文章无法确认时标记为待整理。
- 允许补充 `title`、`author`、`applicationYear`、`publishedAt`、`updatedAt`、`summary`、`cover`、`coverAlt`、`sourceUrl` 和 `draft` 等展示与索引字段。
- 不新增 `appliedSchools`、`stages` 或 `tags`；申请院校、夏令营/预推免等阶段和其他分类信息继续留在正文中。
- 作者署名保留原文中的真实姓名、昵称或匿名方式。稳定 ID 由维护者确定，默认使用不会随标题修改而变化的简短标识。
- 正文原样保留，包括语气、顺序、表格、链接和原有免责声明。仅对图片/附件相对路径做机械性修正，不能借迁移机会改写文字。

## 图片和附件规则

- 原始文章已有的图片和附件全部列入迁移清单，保留与对应文章的归属关系。一个人的材料不能散落到公共目录中。
- 每个附件逐项审核后才进入项目仓库：确认投稿者允许公开、文件不含不应公开的个人信息或内部材料、格式能被静态站点安全托管。
- 审核通过后再复制到文章目录，并把正文中的引用改为新的相对路径；审核不通过的文件留在 `references/`，不进入生产仓库。
- 旧站文章目录中的封面图可用于核对历史展示，但优先使用原始经验仓库提供的图片。旧站只有封面、原始文章没有对应文件时，需人工确认是否可以继续公开后再采用。
- 没有投稿图片的历史文章可不设置专属封面；若需要统一列表视觉，由维护者选择全站默认封面。新投稿默认一张可选封面，不能用学校图片作为强制封面。
- 当前已知包含额外附件的文章是 `SummerCamp/2025/Leo/`：5 张 PNG、1 个 DOCX 和一个附件说明 Markdown；这些文件必须单独审核后再公开。

## 发布前验证

在首次部署前执行一次人工和构建检查：

1. 所有公开文章都具备有效 `applicationYear`、稳定 ID 和可解析的 Markdown。
2. 测试稿不在内容集合中，所有被引用的图片和附件均存在且已审核。
3. 年份列表、文章排序和详情地址符合 `/experiences/2025/<stable-id>/` 约定。
4. 旧地址重定向清单与实际文章一一对应，不把旧服务或旧联系方式带入新版公开页面。
5. Astro 构建成功，站内图片、附件、文章内锚点和外部链接抽查通过。
